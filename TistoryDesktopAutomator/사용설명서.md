# 티스토리 Windows 자동 글쓰기 프로그램

**방식:** 로그인된 Google Chrome을 실제 마우스/키보드로 제어합니다. 티스토리 API, Selenium, Playwright, 브라우저 개발자도구, HTML DOM 접근, 서버 호출은 사용하지 않습니다. 엑셀 읽기에는 `openpyxl`을, 화면 조작에는 `PyAutoGUI`를 사용합니다.

## 제공 파일

| 파일 | 설명 |
|---|---|
| `tistory_desktop.py` | Windows용 GUI 본체 |
| `샘플_게시글.xlsx` | 제목, 본문, 실행(Y/N), 메모가 있는 엑셀 양식 |
| `requirements.txt` | Python 라이브러리 설치 목록 |
| `설치.bat` | Python 설치 후 필요한 패키지를 설치 |
| `실행.bat` | 자동 글쓰기 프로그램 실행 |
| `EXE만들기.bat` | Windows에서 배포용 exe 만들기 (선택) |

## 1. 설치

1. Windows 10/11, Chrome, Python 3.11 이상이 필요합니다. Python은 설치할 때 **Add Python to PATH**를 선택하세요.
2. ZIP 파일을 실제 폴더에 **모두 압축 해제**합니다. ZIP 내부에서 바로 실행하지 마세요.
3. `설치.bat`을 더블클릭한 뒤 설치가 끝나면 `실행.bat`을 더블클릭합니다.
4. Chrome에서 블로그에 직접 로그인합니다. **자동화 실행 중에는 크롬을 직접 조작하지 않습니다.** 인증/보안문자가 뜨면 자동화를 중지하고 수동으로 처리합니다.

## 2. 엑셀 준비

1행은 `제목`, `본문`, `실행`, `메모`여야 합니다.

| 제목 | 본문 | 실행 | 메모 |
|---|---|---|---|
| 오늘의 일기 | 오늘은 날씨가 좋았습니다. | Y | 실행 대상 |
| 테스트 글 | 줄바꿈이 있는 텍스트도 가능 | N | 제외 |

- **실행 열이 `Y`인 행만** 대상으로 삼습니다. `Y`, `YES`, `1`, `TRUE`, `발행` 허용.
- 제목과 본문은 문자열로 읽으며, **이미지, 표, 글꼴, 하이퍼링크 서식**을 그대로 복원하지는 않습니다.
- 여러 줄 본문은 한 셀 안에서 `Alt+Enter`로 입력하세요.
- 다른 작업 중 Excel을 수정하지 마세요.
- 테스트는 `Y`인 첫 행 1개만 수행합니다.

## 3. 티스토리 주소 입력

로그인된 Chrome에서 아래 페이지를 수동으로 열고 **주소창 그대로 복사**하여 프로그램에 입력하세요. 자동으로 특정 관리 URL을 추정하지 않습니다.

1. **블로그 홈 URL:** 실제로 발행 글이 보이는 도메인 첫 페이지 (예: `https://example.tistory.com/`). 사용자 지정 도메인이라면 실제 사용자 지정 도메인을 입력합니다.
2. **글쓰기 URL:** [글쓰기] 버튼을 눌러 열린 새 글쓰기 화면의 주소.
3. **글 관리 URL:** [글 관리] 메뉴에서 글 목록이 보이는 화면의 주소.

테스트 중은 크롬을 최대화하고 **Zoom 100% (Ctrl+0)** 로 맞춘 후 위치를 지정하세요. Windows 디스플레이 배율, 해상도, 크롬 창 크기를 고정하세요. 작업할 Chrome 프로필을 하나만 열어두는 것이 좋습니다.

## 4. 화면 위치 설정 (최초 1회)

프로그램의 `클릭 위치 설정` 탭에서 각 버튼을 클릭하세요. 프로그램 창이 **5초간 숨겨지는 동안** Chrome의 해당 위치에 **마우스를 갖다 대기만** 하면 저장됩니다. 클릭하지 마세요.

- **제목 입력칸:** 새 글쓰기 화면에서 제목 텍스트를 입력하는 지점.
- **본문 입력칸:** 새 글쓰기 화면에서 본문 텍스트를 입력하는 지점.
- **완료 버튼:** 에디터에서 발행 옵션을 여는 첫 번째 완료 버튼.
- **공개 선택 항목:** 발행 옵션 중 [공개] 위치. 공개 자동 설정을 선택했을 때만 사용.
- **발행 버튼:** [완료] 후 나타나는 발행 옵션 화면의 **최종 발행 버튼**.
- **최신 글 보기:** 글 관리 화면에서 가장 최근 게시물의 [보기] 링크나 아이콘 (실제 게시글로 이동하는 위치). **반드시 가장 최근 글이 목록 첫 번째인지 확인**하세요.

> **중요:** 티스토리 화면 레이아웃은 계정과 서비스 개편에 따라 달라질 수 있습니다. 실제 발행 버튼 이름/위치와 URL은 본인 화면에서 직접 확인해야 합니다. 발행 후 글 관리 첫 행이 최종 게시글인지 확인하는 검증을 추가했습니다. 글 관리 화면에서 [보기] 링크가 별도 탭으로 열리면 프로그램이 다음 탭으로 이동해 확인을 시도합니다.

## 5. 순서

1. `샘플_게시글.xlsx`에서 실행할 글의 `실행` 열만 Y로 변경합니다.
2. 실행 탭에서 Excel, 블로그 홈, 글쓰기, 글 관리 URL을 입력합니다.
3. `엑셀 검사`를 눌러 대상 개수를 확인합니다.
4. 모든 화면 좌표를 지정하고 `설정 저장`을 누릅니다.
5. **테스트 모드 ON**에서 `자동 작성 시작`. 첫 Y행 제목/본문을 입력하고 `draft.png`를 저장하지만 실제로 발행하지 않습니다. Chrome에 테스트 미발행 글이 남아 있으면 삭제하거나 새 글쓰기로 초기화하세요.
6. 입력이 정상임을 눈으로 확인한 뒤 **테스트 모드 OFF**로 변경하고 `자동 작성 시작`을 누릅니다.
7. 프로그램이 제목/본문을 입력 → 클립보드로 입력내용 검증 → 완료 → 발행 → 글 관리 → 최신 글 보기 → 게시글 최종 검증 → 화면 캡처 순으로 진행합니다.
8. **검증에 실패한 건은 즉시 멈춥니다.** 재실행해도 이미 발행 시도한 글은 자동으로 다시 발행하지 않습니다. 먼저 실제 글 관리 상태를 확인하세요.

## 6. 결과 위치와 상태

`results/블로그주소/YYYYMMDD/report.csv`에서 행별 실행 결과를 확인할 수 있습니다. Excel에서 열 수 있는 UTF-8 CSV입니다.

각 행마다 별도 폴더를 만들어 다음을 저장합니다.

- `draft.png`: 발행 전 입력 화면.
- `publish_dialog.png`: 최종 발행 옵션이 열린 화면.
- `post_click.png`: 최종 발행 버튼 클릭 직후 화면.
- `manage_list.png`: 티스토리 글 관리 화면.
- `published_01.png` 등: 실제 게시글 화면 및 스크롤 후 캡처 (1~6장).
- `error_screen.png`: 오류 당시 화면 (실패 시).

확인 상태:

- `TEST_ONLY_NOT_PUBLISHED`: 테스트 입력 완료, 글은 발행되지 않음.
- `VERIFIED`: 실제 게시글 주소 + 제목 + 본문 샘플(짧은 글은 전체) 확인.
- `FAILED_BEFORE_PUBLISH`: 발행 클릭 전 실패. 좌표를 수정한 뒤 재시도 가능.
- `REVIEW_REQUIRED_NO_RETRY`: 최종 발행을 시도했지만 성공 확인 실패. **수동 점검 후 조치**.

`results/블로그주소/ledger.json`에는 발행 시도 이력이 남습니다. 임의로 삭제하면 중복 게시 위험이 생기므로 삭제하지 마세요.

## 7. 검증 방법과 제약

- 발행 전에 제목/본문 칸에서 키보드 `Ctrl+A, Ctrl+C`를 수행해 엑셀 원본과 비교합니다. 화면의 리치 에디터/브라우저 특성에 따라 클립보드로 복사되지 않는 경우 **실패 처리**합니다.
- 글 관리 목록에 원본 제목이 있는지 확인한 뒤, 좌표로 설정한 최신 글의 `보기`를 엽니다.
- 열린 게시글이 입력한 블로그 도메인이고 관리 페이지가 아닌지 검증합니다.
- 브라우저 페이지에서 `Ctrl+A, Ctrl+C`로 복사한 텍스트에서 원본 제목과 본문을 확인합니다. 본문이 220자 이하이면 전체를, 더 길면 앞·중간·뒤 각 65~120자를 확인합니다.
- 스크린샷은 기본 3장, 최대 6장입니다. **게시글이 매우 길면 전체를 담지 못할 수 있습니다.**
- 광고, 위젯, 블로그 스킨, 외부 링크, 서식 등에 따라 본문 검증이 실패하거나 다른 위치의 동일한 문구가 검증에 영향을 줄 수 있으므로 완벽한 증명으로 간주하지 마세요.
- 글 관리 목록 정렬이 최신순이 아니거나, 같은 제목의 오래된 글이 있는 경우 확인이 필요합니다.
- 프로그램은 본문 텍스트 입력만 지원합니다. `본문` 셀에 HTML을 넣으면 HTML 문자열로 붙여넣을 수 있고, HTML 렌더링으로 자동 변환하지 않습니다.
- 블로그의 공개 여부/발행 정책 및 이용약관을 준수하고, 다량·중복·광고성 게시를 하지 마세요. 자동화 접속 차단 또는 보안검사가 나타나면 중지해야 합니다.
- 멀티 모니터 환경에서는 **주 모니터**에 크롬을 놓으세요. PyAutoGUI의 이미지/좌표 기능은 주 모니터를 기준으로 작동합니다.
- 마우스를 화면의 모서리로 이동하면 PyAutoGUI의 안전 중단 기능이 동작합니다.

## 8. Windows EXE 파일 만들기 (선택)

`EXE만들기.bat`을 실행하면 해당 Windows에서 `dist/tistory_desktop.exe` 단독 실행 파일이 생성됩니다. Python 설치가 필요 없는 배포용 EXE를 만들 때 사용합니다. **현재 패키지는 파이썬 소스 실행형이며 Linux 환경에서 Windows EXE를 미리 빌드하지 않았습니다.**

> 자동화는 **사용자 PC에서만 실행**되고, 입력 데이터는 사용자가 지정한 엑셀 파일에서 로컬로 읽습니다. 프로그램 자체는 블로그 API 요청이나 AI 서버 데이터 업로드 코드를 포함하지 않습니다.
